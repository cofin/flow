# Flow Project Context

Flow is a multi-harness Spec-Driven Development plugin for **Google Antigravity**, **Claude Code**, **Codex CLI**, **Cursor**, **OpenCode V2**, and **VS Code / Copilot**. Flow has no `flow` shell executable; invoke the [`flow`](skills/flow/SKILL.md) skill or a `/flow:*` command.

## Architecture & Routing

- **Lifecycle Router**: [skills/flow/SKILL.md](skills/flow/SKILL.md) routes across [`flow-setup`](skills/flow-setup/SKILL.md) (`setup`), [`flow-planning`](skills/flow-planning/SKILL.md) (`prd`, `plan`, `revise` [alias `refine`], `research` [alias `task`]), [`flow-execution`](skills/flow-execution/SKILL.md) (`implement`, `status`), [`flow-learn`](skills/flow-learn/SKILL.md) (`learn` [aliases `resynthesize`, `refresh`, `sync`]), [`flow-docs`](skills/flow-docs/SKILL.md) (`docs` [subcommands `write`, `validate`, `capture`, `sync`, `pr`]), and [`flow-completion`](skills/flow-completion/SKILL.md) (`review`, `finish`, `archive`, `cleanup`, `revert`, `validate`).
- **Foundation & Harness Skills**: [`okf`](skills/okf/SKILL.md) (`OKF v0.2` knowledge bundles and provenance), [`debloat`](skills/debloat/SKILL.md) (deep-module deletion test, public-seam test strength, and anti-slop prose/context pruning), and [`multi-harness-plugins`](skills/multi-harness-plugins/SKILL.md) (project-local `.agents/` and multi-harness skill, subagent, hook, rule, and MCP standards).
- **Stateful Planning vs. Subagent-Managed Chapters & Zero-Context Verification**: Stateful Co-Designers/Adjudicators (`@prd-orchestrator`, `@plan-generator`) decompose multi-module work into context-bounded chapters (`specs/<flow_id>/chapters/ch01-<slug>/..chNN-<slug>/`, `1–4` vertical-slice tasks per chapter, zero upper cap on chapter count) authored upfront in parallel subagents without truncating engineering or documentation detail; Zero-Context Reviewers & Isolated Executors (`@code-reviewer`, `@quality-reviewer`, `@researcher`, `@executor`) operate under Zero-Context Isolation Rules, Bounded Read Manifests, Public-Seam Vertical-Slice TDD, and cross-harness `Stop` review/sync hooks.
- **Present-Tense Direct Markdown State Contract**: Root specifications (`.agents/bundles/specs/<flow_id>/spec.md`), chapter catalogs (`chapters/index.md`), chapter specs (`chapters/<ch_id>/spec.md`), and task worksheets (`tasks/<id>-<slug>.md`) are kept synchronized in place in present tense—showing current verified state, remaining chapters, and the full plan without historical sediment ([`skills/flow/references/state.md`](skills/flow/references/state.md)).

## Discipline

Initialize with [the setup guide](skills/flow/references/setup.md), then use `.agents/bundles/index.md`, `.agents/bundles/knowledge/workflow.md`, and `.agents/skills/index.md`. Execute one worksheet per subagent turn (`model: inherit`) and strictly one chapter per `/flow:implement` run (syncing present-tense OKF/docs and passing zero-context chapter review before stopping), preserve unrelated work, stage exact paths, and commit locally only after verification passes. Never create or mutate Git tags. Pushes and remote writes require explicit user instruction.
