# Flow Project Context

Flow is a multi-harness Spec-Driven Development plugin for **Google Antigravity**, **Claude Code**, **Codex CLI**, **Cursor**, **OpenCode V2**, and **VS Code / Copilot**. Flow has no `flow` shell executable; invoke the [`flow`](skills/flow/SKILL.md) skill or a `/flow:*` command.

## Architecture & Routing

- **Lifecycle Router**: [skills/flow/SKILL.md](skills/flow/SKILL.md) routes across [`flow-setup`](skills/flow-setup/SKILL.md) (`setup`), [`flow-planning`](skills/flow-planning/SKILL.md) (`prd`, `spec` [alias `plan`], `revise` [alias `refine`], `research` [alias `task`]), [`flow-execution`](skills/flow-execution/SKILL.md) (`implement`, `status`), [`flow-learn`](skills/flow-learn/SKILL.md) (`learn` [aliases `resynthesize`, `refresh`, `sync`]), [`flow-docs`](skills/flow-docs/SKILL.md) (`docs` [subcommands `write`, `validate`, `capture`, `sync`, `pr`]), and [`flow-completion`](skills/flow-completion/SKILL.md) (`review`, `finish`, `archive`, `cleanup`, `revert`, `validate`).
- **Foundation & Harness Skills**: [`okf`](skills/okf/SKILL.md) (`OKF v0.2` knowledge bundles and provenance), [`debloat`](skills/debloat/SKILL.md) (deep-module deletion test, public-seam test strength, and anti-slop prose/context pruning), and [`multi-harness-plugins`](skills/multi-harness-plugins/SKILL.md) (project-local `.agents/` and multi-harness skill, subagent, hook, rule, and MCP standards).
- **Stateful Planning vs. Subagent-Managed Chapters & Zero-Context Verification**: Stateful Co-Designers/Adjudicators (`@prd-orchestrator`, `@plan-generator`) default cohesive single-deliverable features to one concise single-chapter `spec.md` (`has_chapters: false`) and split into `ch01-<slug>/..chNN-<slug>/` only at genuine checkpoints, independent parallel subsystems, or `empirical_dependent` gates—with zero artificial limits on chapter task count, `read_set`, or LOC, `compact` worksheets allowed across all tiers, parallel per-chapter planners when `>= 2` chapters exist, and Frontier Pro quota reserved strictly for planning and cold-read spec review; Zero-Context Reviewers & Isolated Executors (`@code-reviewer`, `@quality-reviewer`, `@researcher`, `@executor`) operate under Zero-Context Isolation Rules, Bounded Read Manifests, parallel disjoint workers (`small_swarm` on Antigravity; `parallel_subagents` on Claude Code, Codex CLI, Cursor, and OpenCode) or bounded `<= 5`-task Flash/Sonnet worker batches, Public-Seam Vertical-Slice TDD, and cross-harness `Stop` anti-skip review/sync hooks.
- **Present-Tense Direct Markdown State Contract**: Root specifications (`.agents/bundles/specs/<flow_id>/spec.md`), chapter catalogs (`chapters/index.md`), chapter specs (`chapters/<ch_id>/spec.md`), and task worksheets (`tasks/<id>-<slug>.md`) are kept synchronized in place in present tense—showing current verified state, remaining chapters, and the full plan without historical sediment ([`skills/flow/references/state.md`](skills/flow/references/state.md)).

## Discipline

Initialize with [the setup guide](skills/flow/references/setup.md), then use `.agents/bundles/index.md`, `.agents/bundles/knowledge/workflow.md`, and `.agents/skills/index.md`. Execute one active chapter per `/flow:implement` run (or consecutive ready chapters with `--all`), splitting `> 5`-task chapters across parallel disjoint workers (`<= 3` writers, `<= 5` tasks/worker) or bounded `<= 5`-task `chapter_batch` chunks, validating with the `< 60s` Fast Chapter Gate, syncing present-tense OKF/docs, and passing zero-context chapter review before stopping, while preserving unrelated work, staging exact paths, and committing locally only after verification passes. Never create or mutate Git tags. Pushes and remote writes require explicit user instruction.
